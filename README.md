# Практическая работа №2 — вариант 30
CLI-инструмент построения графа зависимостей npm-пакетов. Требуется Node.js 18+. Сторонние библиотеки и команды npm/yarn/pnpm для получения зависимостей не используются: применяется встроенный fetch и npm Registry API.

## Этап 1. Минимальный прототип и параметры CLI
| Опция | Назначение | По умолчанию |
|---|---|---|
| --package <имя> | анализируемый пакет | обязательно |
| --repository <URL|путь> | npm Registry или JSON-файл | https://registry.npmjs.org |
| --test-mode | тестовый режим | выключен |
| --version <версия> | версия корневого пакета | latest |
| --output <файл> | имя выходного файла графа | dependency-graph.dot |
| --max-depth <N> | максимальная глубина анализа | 3 |

Параметры печатаются в формате ключ=значение. Проверяются обязательность и формат имени пакета, URL/путь, версия, глубина, неизвестные опции, повторные опции и отсутствие значений. --help выводит справку.

## Этап 2. Сбор данных
Используется формат npm. Для заданной версии запрашивается метаданные пакета из npm Registry, выбирается запись versions и извлекаются прямые зависимости из dependencies и optionalDependencies. Поддерживаются scoped-пакеты. Прямые зависимости выводятся на экран; HTTP-ошибки и отсутствующие версии сопровождаются диагностикой.

## Этап 3. Основные операции
Граф строится **итеративным BFS без рекурсии** с очередью. Соблюдается --max-depth. Множество посещённых узлов не допускает повторного обхода, но рёбра сохраняются, поэтому циклы и общие зависимости обрабатываются корректно. Для транзитивных пакетов используется dist-tag latest.

Тестовый режим читает JSON-файл с именами пакетов из заглавных латинских букв. test-repos/sample.json содержит цикл A→B→D→A и общую зависимость D; isolated.json демонстрирует пакет без зависимостей.

## Запуск
```bash
npm test
npm start -- --package express --version 4.18.2 --max-depth 2
npm start -- --package A --test-mode --repository test-repos/sample.json --max-depth 5
npm start -- --package A --test-mode --repository test-repos/isolated.json
npm start -- --package express --repository https://registry.npmjs.org --version latest --max-depth 1
```
Справка: `npm start -- --help`.

## Пример обхода
При старте с A и глубине 2 раскрываются A (0), B и C (1), D и E (2). Ребро D→A остаётся в графе, повторный обход A не производится; общий узел D учитывается один раз.

## Ограничения
Для транзитивных пакетов берётся latest, а не выполняется полноценное разрешение semver-диапазонов. Поэтому результат может отличаться от локального npm ls, который учитывает установленные версии и lock-файл. Визуализация и обратные зависимости относятся к этапам 4–5 и здесь не реализованы.
